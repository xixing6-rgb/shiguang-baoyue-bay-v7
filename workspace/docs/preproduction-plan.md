## 一、《动森.txt》剥离商业化后的平台可行性审计

经过对抖音造世界（`douyin-world` CLI + Hamlet Lua 白名单 + AI Editor WPrefab 管线）实测能力与硬边界的交叉核对，**《动森.txt》中的核心纯体验玩法可以放进平台**，但渲染、画板、语音和模块化方式必须按平台边界做针对性重构。

### 1.1 可 100% 原生落地的纯体验内核（纯 Lua 5.3 + Unity 白名单 + Hamlet SDK）

| 核心模块 | 平台可行依据 | 落地方式 |
| :--- | :--- | :--- |
| **Smart Objects + Utility AI 自主心智** | 开放 `UnityEngine`、`UnityEngine.AI` 寻路、Transform/物理与 Lua 协程/Update | 家具与道具挂载“广播组件”（声明满足的动机、交互槽位数与动作 ID），居民周期扫描附近广播并按性格/微个性权重做 0–1 效用加权抽选 |
| **性格 × 解耦微个性 + 轻推（つまむ）** | 支持鼠标/触控射线拾取、Transform 控制与 Runtime UI 提示 | 16 性格滑杆 + 独立微个性标签（面瘫/大胃王/走秀步态/漂浮等）；玩家可“抓起居民放到某处”，但不提供强制恋爱/服从按钮，保留“不配合”的喜剧感 |
| **四色烦恼气泡 & 0–255 零惩罚好感** | 支持世界坐标投屏 UI / 头顶 Sprite、Lua 内存状态与 `DouyinDataStore` | 黄（饮食穿搭）/橙（友谊）/粉（告白）/紫（物理滑稽意外）气泡分诊；好感度只增不因缺席扣减，坚决不设 Game Over 或倒计时剥夺 |
| **孟德尔花卉杂交 / 食物隐藏偏好矩阵** | 纯 Lua 数学与表结构计算，不依赖外部服务 | 简化版 2–3 对等位基因遗传（含显隐性与单株无性克隆）；或 50–100 种食物隐藏偏好分布矩阵 |
| **黑板事实规则库 + Tracery 词库涌现** | 纯 Lua 表匹配与字符串模板展开，零云端大模型延迟与审核风险 | 内存维护轻量黑板表（时辰、天气、昨日动作、好感、偶遇），结合玩家输入的流行语/昵称生成贴合当下的荒诞台词与小岛新闻 |
| **RTC 现实时间 + 确定性气象种子** | Lua 白名单开放 `os.time` / `os.date` / `os.clock` | 基于玩家设备或房间时间驱动昼夜、物候提示与天气序列；结合 `scene environment` 或 Lua 环境平滑过渡 |
| **异步人际记忆 & 多人串门** | 支持 `SharedMode` 多人同步、`---@varSync`、主权流转与 `DouyinDataStore` | 串门交互不强求 12 人重同步，聚焦 2–4 人轻松游览与“居民跨访转述好友昨日趣事”的异步交换日记体验 |

### 1.2 受限于平台边界的 4 处硬约束与工程替代方案

| 原文方案 | 抖音造世界平台限制（已核验） | 本项目替代实现方案 |
| :--- | :--- | :--- |
| **1. 滚木弯曲地平线 Shader & GPU 顶点风场** | **不允许编写自定义 Shader / HLSL / URP RenderFeature**；不能用自定义顶点色风场着色器 | ① 在 SCAD / Blender 中将岛屿或庭院做成**微微圆润隆起的真实微弧穹顶地形**（半径取平缓过渡，避免物理错位）；<br>② 用 `DouyinCameraService` 设置低俯微缩斜视角，配合官方线性远景雾与天空盒强化“圆球小岛延展感”；<br>③ 树木/旗帜用轻量 Lua 低频局部正弦微摆 + 粒子飘落（花瓣/树叶模板）表现风力。 |
| **2. 高自由度运行时位图画板 & 跨端涂鸦同步** | 无内置自由笔刷画板控件；**`DouyinDataStore` 单条 JSON 约 6000 字符上限**，不适合传大图像素数组 | ① **8×8 或 12×12 像素点阵涂鸦板**（Runtime UI 按钮网格 + 6–8 色调色板，编码为紧凑字符串仅约 **150–220 字节**），可用于绘小旗、木牌或 T 恤胸徽；<br>② **预设 2D 贴纸拼装 + Runtime UI `input` 注入岛屿流行语/口癖**，零绘制门槛同样激活宜家效应。 |
| **3. 离线 C++/DLL TTS 插件（eSpeak-ng/SAM）** | Lua 沙箱禁止 C# 原生插件、`xlua.load_assembly`、Android JNI 与 `UnityWebRequest`（不可直连外部 HTTP TTS/LLM） | 采用**外部离线音频切片 + Lua 动态变调**方案：准备 10–16 个 60–120ms 的短音频切片（软萌元音包 / 机械方波电音包）归档为官方音频资产；Lua 打字机输出台词时按字符哈希 + 性格基频 + 体型/情绪偏移实时调节 `AudioSource.pitch` 与播放间隔。 |
| **4. 自由写实光影、自定义天空盒与多后处理** | `lightData` 未暴露阴影字段；天空盒/反射**仅限官方预设 `cubeimage` 候选**（白天/夕阳/夜晚/星空/雨/雪）；后处理仅开放 Bloom 与 Vignette | ① 遵循 Valdez & Mehrabian 高明度（B）低饱和（S）柔色色板，压制地面纹理噪点，凸显“游玩契机”；<br>② **核心视觉杠杆：用本机 Blender 将直接光与间接光（GI）静态烘焙进 UV0 颜色图**，通过 Emission 适配导入，搭配少量点光烘托夜景窗光。 |

> **额外的脚本与 UI 架构边界**：AI Editor 不自建 Lua `ModuleScript` 或自定义 Loader，也不交付独立 DS 服务端。所有玩法拆分为独立的 `DouyinScript` 文件，只 `require("official.*")` 官方模块，通过 **Runtime Host 协调脚本 + `RuntimeScope`** 管理全局状态；Runtime UI 必须用静态 HTML DSL + PNG/SVG 编译，不可使用 `<script>`/`<style>`/CSS 圆角边框（圆角须用图片底板），且必须避让官方左上、系统右侧及摇杆受保护区域。

   - **`generation start model`（拓扑/3D 模型生成）**：

## 四、分阶段落地计划（WPrefab 工程化路线）

选定方案后，严格按《造世界外部创作》与《动森.txt》倒置开发原则推进：

1. **Phase 0：方向定型与工程对齐**
   - 确认选定方案（A / B / C）及场景生成模式（**高品质模式**或**标准模式**）。
   - 核对并绑定当前活动的造世界编辑器项目与工作区，更新 [project-index.json](file:///c:/Users/29933/Desktop/抖音/project-index.json) 与 [INDEX.md](file:///c:/Users/29933/Desktop/抖音/INDEX.md)。
2. **Phase 1：代表区域与“散步就舒服”的手感基底（先小切片验收）**
   - 用 SCAD / Blender 搭建微弧基底与 1 处代表区域（如 1 棵果树 + 1 张长椅 + 1 块花圃/黑板），配置 Layer（地面 `Default(0)` / 自由道具 `Props(6)`）与足音/镜头。
   - 导入主场景、运行 `runtime start` 并在真实玩家视角截图核验比例、落地与交互。
3. **Phase 2：居民心智与轻推涌现闭环**
   - 召回/生成首批 3 名居民并完成免费 `rig` 与官方动作配置；实现 `Runtime Host` 协调脚本 + Smart Objects 广播 + Utility AI 效用循环 + 物理抓起轻推与四色烦恼气泡。
4. **Phase 3：轻 UGC、规则词库与音节声景**
   - 上线对应特色的轻 UGC（方案 A 花朵遗传 / 方案 B 流行语词库+食物偏好 / 方案 C 12×12 像素旗+流行语黑板+花圃）、黑板事实对话及零插件 Animalese / 机械音节打字机。
5. **Phase 4：品质精修（若选高品质）与保存交付**
   - 调整 `scene environment` 昼夜与雾效、接入粒子模板、用本机 Blender 完成静态 GI 颜色烘焙并复核阴影与动态物体受光；全链路 `validate → build → result archive → scene save` 并留存运行截图证据。
