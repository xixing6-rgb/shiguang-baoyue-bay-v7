# 抱月湾 2.5D 项目审计与四天分工

审计基线为 2026-11-25 的 Git 提交 `8601817`。本次以 README 和 HANDOFF 指定的 `shiguang-25d-windwaker` 为当前产品。四天按 D1–D4 排，负责人拿到任务即可开始。

**当前最影响交付的三个事实**：从磁盘打开的是旧 4× 小镇；农场读写代码与已安装平台的存档接口不符；旧版全量检查即使全部通过，也不会运行现行种菜、对话和重进流程。先解决这三件事，才能判断玩家拿到的究竟是哪一版、进度能否留下。

## 四天合流节奏与截止线

| 时间 | 必须发生的交接 |
| --- | --- |
| D1 收工前 | A 交可恢复的测试副本、目标标识和基线；B、C 对齐“谁结算、谁显示”及宿主接口；D 交验收矩阵和当前红项。实例不可用时 B/C 继续用隔离样例，D 继续静态验收。 |
| D2 收工前 | B 交可往返的存档格式及三作物结果；C 交对话、目标复核和点击入口；A 接入同一候选。D 收首轮结果，优先暴露进度丢失和交互走不通。 |
| D3 中午前 | A 向 D 提供冻结候选及唯一 URI。D 用正常输入跑 A–D 和跨会话恢复，B/C 当天只修复能定位的阻断；有改动由 A 生成新候选并通知 D。 |
| D4 | 整天留给失败复测、保存后重开、恢复交接。D 对同一最终候选给结论；若 P0 未清、收获／赠礼／重进未过或保存未确认，结论标为“未通过”，列失败步骤与最后可恢复版本。 |

**完工口径**：另一位成员按最终交接打开正确版本；出生能落地、桥能走，八格可辨，三种作物可成熟并收获，给两位居民送礼按作物只结算一次，关闭对话恢复操作，重进后田地和账目相符。提交同版本的保存回执、截图及结果记录。无可用手机时，记录实际预览设备和分辨率，将手机帧率与触控标为未验证。

**产品边界**：现行装配绑定相机、农场、对话三份脚本。两个 NPC 共用同一占位模型，现行对白各有四句，继续按钮在末句后回到首句。旧版叙事库、网页里的六章九居民和 62 张建模参考图都有独立用途，不应算作当前可玩的内容。四天演示的终点是“我种的作物送给了邻居，他还记得”，D 按这一条玩家经历验证交付。

**时间不足时的取舍**：先保可恢复的版本、存档和核心输入，其次补性能数据。外部角色绑骨、真实绿幕视频、旧 4× 六章九居民迁移、Kimodo 接入和 P2 网页修补不占本轮关键路径。当前角色继续用已有占位和 6/4 帧。四天目标为团队可验收的本地候选；覆盖原工程、删除既有数据、发布、推送和付费操作仍须由负责人取得用户授权。
